# Facility-level targeting for central-reported checks

This card delivers reported instances, the per-check detail object and instance silences. The follow-up lets an instance name the target it concerns, so that target's own state can gate it.

## Instances name the target they concern

An instance reported on one target can name another target in the same group that it is about, through opaque aliases: an application's report declares the identifiers it is known by (an `aliases` object keyed by kind, one value per kind, e.g. `tamanu-device`), and an instance names the alias it concerns in a `concerns` object of the same shape. Canopy resolves the alias within the reporting application's group and never interprets kinds or values. Aliases persist from an application's last report, since the target most often referenced is the one that has gone quiet. An alias claimed by more than one application in the group resolves to nothing, and an unresolved reference leaves the instance graded on the reporting target's policy alone. A resolved instance is held out of incidents while the target it concerns is unmonitored or under a maintenance window, but does not inherit that target's silences, reachability included. It stays the reporting target's issue for health rollup and incident placement, and is also presented on the target it concerns, marked as reported by the reporting target. Needs a matching bestool change: a facility's alertd declares its `deviceId` (from `local_system_facts`) as a `tamanu-device` alias, and `sync_facility_stale` instances name the device they concern.
