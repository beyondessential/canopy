Instanced check payloads

How a reporter sends one check with several instances, set against today's single-result check. Shapes are for the status push (POST /status/{server_id}), current format.

1. One check, before and after

Central's sync_facility_stale, with one device offline for two days and one healthy.

Today
{
  "check": "sync_facility_stale",
  "result": "failed",
! "fail": [
!   {
!     "facility_id": "facility-northgate",
!     "last_successful_sync": "2026-09-30 08:12:44+00",
!     "minutes_since_success": 2875.4
!   }
! ],
! "warn": [],
  "summary": "stale sync: 1 over 30m, 0 over 10m",
  "reason": "facility sync stale"
}
Instanced
{
  "check": "sync_facility_stale",
  "warn_minutes": 10,
  "fail_minutes": 30,
+ "instances": {
+   "6f1c2a9e-4b7d-4e0a-9c55-2d8e1f3b7a10": {
+     "result": "failed",
+     "label": "Northgate Clinic",
+     "detail": {
+       "facility_ids": ["facility-northgate"],
+       "last_successful_sync": "2026-09-30 08:12:44+00",
+       "minutes_since_success": 2875.4
+     }
+   },
+   "b83e0d47-1f6a-4c2b-8e19-7a4d5c6f0e21": {
+     "result": "passed",
+     "label": "Harbour Hospital, Harbour Maternity",
+     "detail": {
+       "facility_ids": ["facility-harbour", "facility-harbour-mat"],
+       "last_successful_sync": "2026-10-02 23:16:02+00",
+       "minutes_since_success": 1.2
+     }
+   }
+ }
}
Arrays are unreachable. A rule sees check.fail as one array value, and silences have nothing to pin. Silencing one facility means silencing them all.
Keyed by device id. Same contract as applications: unique within the check, stable across pushes. A silence pins the key.
No check-level result. Exactly one of result, healthy, instances. Canopy grades each instance and takes the most urgent one that wasn't skipped.
No summary or reason. Canopy writes the message from graded instances by label, so a silenced device drops out of it.
Shared fields stay flat. Fields beside instances apply to every instance. Rules read check.<field> from the instance's detail first, then the shared fields.
Passing instances are sent. The set is the source's complete truth for the check, so a key left out has recovered.

Graded result. With nothing silenced, sync_facility_stale is failed (Northgate) and its message names Northgate Clinic and Ridge Health Centre.

Machine checks too. The shape is HealthCheck, so machine.health entries can be instanced as well, e.g. one instance per mount.

3. Edge shapes

How Canopy reads the cases a reporter can produce.

Check entryReadingPush
{ "check": "sync_facility_stale", "instances": {} } No instances right now, such as a central with no active facilities. Every instance it held has recovered, so the check is passed. Accepted
Every instance "result": "skipped", or every one silenced The check is skipped, as Canopy's own instanced checks are. Accepted
One instance "result": "broken" That instance keeps its last definite result and also warns, as a broken check does today. Other instances are unaffected. Accepted
Instance with no label Named by its key in the message and wherever it is listed. Accepted
A plain check in one push, instanced in the next Still one state for the check. The plain result stops counting and the instances start. The reverse recovers every instance. Accepted
"result" and "instances" together Ambiguous about which one Canopy should grade. 400
Instance with "healthy": false instead of result The legacy boolean is for old checks only. An instance takes result. 400
Instance key "" A key has to identify something. 400

5. Separate card: what an instance concerns

Layer 2, to show the instance object has room for it. The facility declares an alias and central's instance points at it.

Facility's push, its application
{
  "host-tamanu-facility": {
    "type": "tamanu-facility",
+   "aliases": {
+     "tamanu-device": "6f1c2a9e-4b7d-4e0a-9c55-2d8e1f3b7a10"
+   },
    "health": [ … ],
    "detail": { "tamanuVersion": "2.40.1" }
  }
}
Central's instance
"6f1c2a9e-4b7d-4e0a-9c55-2d8e1f3b7a10": {
  "result": "failed",
  "label": "Northgate Clinic",
+ "concerns": {
+   "tamanu-device": "6f1c2a9e-4b7d-4e0a-9c55-2d8e1f3b7a10"
+ },
  "detail": { … }
}
One value per kind. Keyed by kind, so an application cannot claim two device ids. Canopy keeps the last set reported.
Resolved in central's group. If Northgate's application is unmonitored or under maintenance, this instance is held out. Its silences do not apply.
